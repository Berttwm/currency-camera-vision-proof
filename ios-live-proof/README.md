# Live currency-filter capability proof

This is a diagnostic, not a currency converter or a product release. It tests the separate public VisionKit live `.currency` text filter, available since iOS17. Failure of the earlier string/document experiments does not measure this filter. No price accuracy, physical iPhone compatibility, free installation, latency or label-stability PASS exists yet.

One screen uses Apple's camera and native highlights. Tap Start test: 40 seconds of currency-filtered text, then a fresh scanner for 40 seconds of all text. Both use accurate quality, automatic language selection, multiple items, high-frame-rate tracking and no pinch zoom. These flags do not prove optical-flow support in the filtered mode. The app adds no price heuristics, conversions, API keys, server, network requests or third-party packages.

Every half second it records raw transcripts, native item IDs, scanner-view quadrilaterals and OCR candidates/confidences. At elapsed6/16/26/36/46/56/66/76 seconds it requests a high-resolution photo and records nearby detailed observations. Photos are output only: no saved-image/video input to this scanner is used. Camera capture and observations are **not promised to share an exposure, orientation or crop**. View points and normalized Vision coordinates stay separate. Preserve both the returned transcript and underlying candidate text; substring ranges belong only to that candidate. Confidence is an OCR observation, not a probability that an amount is a retail price.

Each trial creates a unique local Documents directory, excluded from device backup, containing events.jsonl and up to8 JPEGs. The app does not write to Photos or iCloud. USB file sharing is enabled for later owner-approved PC retrieval; the app does not upload evidence. Prior sessions are never overwritten or deleted. Stop, backgrounding, camera errors and recording limits keep partial output. Late photo results from an abandoned trial are not adopted by another trial. Each photo request must begin within3 seconds of its scheduled time. A complete footer requires four saved photos in each timed phase; it never means recognition passed.

Evidence limits: log below16MB (2KB reserved footer), individual photo below16MB, photos together below64MB. Exceeding a limit ends the trial as incomplete; no text/image truncation is used to conceal a failure. A file write failure may leave partial JSON or an unindexed JPEG; retain those files too.

The private pre-result protocol fixes a generated marked/unmarked-price and quantity control plus all3 previously annotated public menus, unchanged109 prices/27 eligible generic values. A repeated40-second PC display allows comparison across the two modes. Agent scoring must inspect what the phone actually saw and preserve every miss/false price. A display recapture changes pixels; it is not identical-image replay. No phone evidence is publicized by this repository. No normalized-photo mapping, moving-label gate or full converter claim follows from this raw diagnostic.

## Free build check, after explicit approval

The manual camera workflow uses the standard public macOS26 runner and an already installed iOS26 Simulator; it downloads no SDK/runtime. It runs the Foundation record self-check, builds/launches a normally ad-hoc-signed Simulator app in **availability-only mode** (no camera permission or scanning), and preserves the measured isSupported/isAvailable Booleans. Neither Boolean is assumed in advance. This is guard/build evidence, not filter recognition.

It separately compiles an **unsigned physical-device IPA** without Apple account, team, certificate or profile. A bounded length/SHA256/base64 envelope in the public run log preserves that binary without another upload action. Source, build metadata, guard output and the unsigned binary become public. If output exceeds its cap the run fails and keeps its failure; no fallback service is used.

A device IPA is not directly installable until owner-controlled local signing. The researched free Windows candidate is direct AltServer sideloading, with weekly renewal; exact reported iOS26.7 compatibility is unverified. Account authentication, device trust, camera permission and installation are separate owner boundaries. The build workflow performs none of them. Public source/build approval is not permission to upload camera evidence, change account/billing or release the web app.
