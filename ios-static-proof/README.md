# Static iOS Simulator comparison — diagnostic revision

Eight text files prepare one free standard `macos-26` job and a tiny Simulator app. The owner approved public test-source publication and necessary reviewed fixes within these eight paths on22October2026. No Apple account, API key, provisioning changes, paid service, phone install or app deployment is part of this experiment.

The manual public-only job downloads the same three public PDFs in `sources.json`, verifies their frozen hashes and renders each full first page once at a uniform 2600-pixel long edge. It writes raw RGBA8, premultiplied-last, big-endian, DeviceRGB inputs in the ephemeral runner. The same shared loader verifies byte counts, dimensions, stride and raw SHA256 before recognition on both Mac and iOS. No UIKit image decode, resize or second menu renderer is used. Both platforms receive identical menu bytes; DeviceRGB is device-dependent, so identical internal color interpretation is not established. SDK/runtime differences remain.

The project has one UIKit application target, shared Swift declarations and a shared build scheme. Its legacy AppDelegate window is intentionally limited to this iOS26 test; newer scene-only requirements are outside scope. Its source excludes the Mac `main.swift`. It bundles only the runner-generated public inputs. The app has no network, camera or account flow; it reads its bundle and atomically writes bounded JSON to Documents. The host reads that file back and verifies completion, actual iOS26 runtime, app source revision and identical pixel metadata. The runner selects an installed available iPhone Simulator from the actual inventory; it never downloads a runtime. No exact iOS26.7 runtime or physical-phone result is promised.
